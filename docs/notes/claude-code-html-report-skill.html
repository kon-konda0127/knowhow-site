Claude Code HTML出力をコンサル品質に整えるスキル

カテゴリ: AI開発 > Claude Code活用 更新: 2026-08-13 📖 約3分で読めます
#ClaudeCode #スキル #HTML出力 #資料作成

# なぜ重要か

スキル（AIに読ませる作法書）を1つ入れるだけで、AIのHTML資料が「枠と箱だらけの野暮ったい見た目」から「余白と文字の階層で見せるコンサル資料級」に変わる。

AIの生成物が没個性なテンプレ見た目（いわゆるAI slop）に収束する問題への、具体的で再現可能な対策例。

# しくみ（なぜ効くか）

  • スキルとは、特定の頼み方をした瞬間だけAIが読み込む「作法書」
  • この html-report-design スキルは「HTMLで出して」と言った時だけ働く
  • 中身は「禁止と強制」の組み合わせ。禁止するのは枠線・グラデーション・絵文字（AIが多用しがちな装飾）
  • 強制するのは、完成済みCSSを使うことと、各セクションを「見出し→結論1文→根拠」の順にすること
  • 図解は5つの型（矢羽根/ロードマップ/フレームワーク表/バブル/滝グラフ）から選ばせ、自由に描かせない
  • 配色は脇役グレー＋主役の濃紺1色。アクセント色だけ会社カラーに差し替え可能
  • 凡例を作らずグラフに直接ラベルを書く
  • 効く理由: 「センス良く」という曖昧な指示ではなく、判断基準を作法書として渡すから毎回同じ品質が出る
  • A4印刷でそのまま配布できる想定

# うちの体制ではこう使う

  • 「AI生成UIは放っておくとテンプレ的な見た目に収束する」問題は、当サイトの開発でも実際に直面した
  • 対処として、チーム規程に「配色・余白・タイポグラフィの判断基準を毎回明示的に適用する」というルールを入れている
  • このスキルはその「判断基準の明文化」を資料デザイン領域でパッケージ化したもの。発想は同じで、対象がUIか資料かの違い

# 導入方法 ※SNS情報・未検証

元ポストの記載の要約。導入する場合は、事前にリポジトリの実在・作者・スター数・ライセンス・SKILL.mdの中身（危険な指示がないか）を裏取りしてから。

  • CLIの場合: npx skills add Ted0321/kotetsu-work-ai-skills@html-report-design
  • Claude Codeに「このリポジトリの skills/html-report-design を ~/.claude/skills/ に入れて」と依頼する方法も紹介されている

# よくあるミス・落とし穴

  • スキルなしで「HTMLで出して」と頼むと枠・グラデ・絵文字まみれになる
  • Claude Code専用ではない（ChatGPT派はSKILL.mdの中身をコピペしても動くとされる ※要確認）
