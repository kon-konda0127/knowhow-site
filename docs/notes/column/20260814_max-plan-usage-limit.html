8月7日に契約して、8月14日でちょうど1週間になりました。使用量の画面を開いたら、最上位モデルのバーだけが赤くなっていました。

「1週間でどのくらい使えるのか」は契約前に一番知りたかったことなのに、どこにも実例がなかった。なので自分の記録を全部数えました。

背景#

筆者はプログラミング初心者です。コードはAI（Claude Code）が書き、自分は指示と判断だけをします。

使い方は「1つの画面で1人と会話する」ではなく、ターミナルを複数開いて同時に別々の作業をさせるやり方に寄っています。この偏りが、そのまま数字に出ています。

数字の出どころは2つ。①アプリが表示するプラン使用状況の画面 ②手元に残るセッション記録を自分で数え直した集計です。私1人・8日間の記録なので、限界は記事の最後に書きます。

事実：1週間で何が起きたか#

8月14日 18時45分のメーター

  • 5時間ごとの枠：9%（1時間54分後にリセット）
  • 週の枠・全モデル合計：63%（8時間14分後にリセット）
  • 週の枠・最上位モデル（Fable）専用：95%（同じく8時間14分後にリセット）

同じ瞬間の数字です。全体には余裕があるのに、上位モデルの枠だけが残り5%でした。

8/11までは1日平均1,260件、8/12以降は4,166件。3.3倍です。前半はまだ「どう頼めばいいか」を探っていて、後半は複数のターミナルを同時に走らせるようになった時期でした。

3番目のSonnet 4.6は前の世代のモデルです。記録には「なぜそのモデルだったか」までは残らないので断言はできませんが、この3,372件を選んで使った覚えは私にはありません。モデルの切り替え忘れだと思っています。

複数のターミナルを開いて別々の作業をさせていると、どのセッションがどのモデルで動いているかが手元で見えなくなります。8月13日に「今どのセッションがどのモデルで動いているか」を一覧するダッシュボードを自作して、初めて全体像が見えるようになりました。

分析：何が枠を減らしていたのか#

数字を並べると、消費のしかたに3つの型が見えました。

  • 枠は2本あり、減り方が違う：全モデル合計の枠（63%）と、最上位モデル専用の枠（95%）は別勘定。上位モデルを使い続けると、全体にはまだ余裕があるのに上位だけ先に止まる。5時間ごとの短期枠は、私が見た範囲では9%止まりで、詰まる原因になりませんでした
  • 減るのは「作業した時間」ではなく「AIとの往復回数」：同時に6セッション動かすと、自分の体感時間は1人分でも消費は6本分。応答数が跳ね上がった8/12〜8/14は、まさに並行作業を始めた時期と一致しています
  • 切り替え忘れは、可視化するまで気づけない：18%という数字は、後から数えて初めて出てきました。作業中は一度も「今このセッションは前の世代で動いている」と気づいていません。手元の画面には出ないからです

考察：1週間使ってみて分かったこと#

  1. 上位モデルの枠は「時間割」ではなく「配給」だった
    契約前は「速度制限つきの使い放題」を想像していました。実際は違います。上位モデルには専用の配給があり、それを何に使うかを自分で決める作業が発生します。週の後半に大きな案件を予定しているなら、前半で使い切ってはいけない。この配分は自動では最適化されません。
  2. 枠が尽きかけた時にやるべきは、止まることではなく割り当て直すこと
    95%を見た時の実際の判断は「今日はもう作業をやめる」ではなく「最上位は翌朝の設計作業に温存し、今日の残りは1つ下のモデルで進める」でした。作業の性質で仕分ければ、枠が残り5%でも1日は止まりません。設計判断や長い文脈を保つ作業は上位、テスト実行・整形・定型の集計は下位で十分です。
  3. 並行作業は、可視化とセットでなければ成立しない
    同時に6つ走らせるのは効率的でしたが、その裏で18%が意図しないモデルに流れていました。並行数を増やすほど、人間の把握できる範囲を超えます。ダッシュボードを自作したのは7日目で、これは遅すぎました。同時に3つ以上動かすなら、最初に「一覧できる状態」を作るべきです。
  4. 枠を使い切るほど回した日が、そのまま成果の多い日ではなかった
    8/13と8/14の2日間で、日報のエントリは60件になりました。ただし中身を読み返すと、監査での差し戻しや、自分の集計ミスの訂正もかなり含まれています。応答数は作業量の目安にはなりますが、価値の目安にはなりません。

この記事の限界#

  • 私1人・8日間の記録です。作業の内容（アプリ開発と運用ルールづくりが中心）や、同時に複数セッションを走らせるという使い方は、かなり偏っています
  • 記事中の「応答18,798件」は手元のセッション記録を自分で数えた数字で、プランの画面に出る%とは計算の単位が違います。両者は一致しませんし、応答1件あたりの重さもモデルや作業内容で変わります
  • 「18%は切り替え忘れ」は、記録から導いた結論ではありません。記録に残るのは「どのモデルが処理したか」だけで、なぜそうなったかは残らない。3,372件という数字は正確ですが、それを切り替え忘れと呼んでいるのは私の記憶が根拠です
  • 一次資料は自分がAIに書かせた作業日報です。うまくいった作業ほど詳しく書かれる偏りが残っています

まとめ：これから契約する人が初日にできること#

  1. 使用量の画面の場所を最初に覚える。 枠が1本ではなく複数ある（短期・全モデル・上位モデル専用）ことを、使い始める前に確認しておく
  2. 週のリセット時刻を把握する。 「あと何時間でリセットか」が分かると、その日の作業の並べ方が変わります
  3. 同時に3つ以上動かすなら、一覧できる仕組みを先に作る。 切り替え忘れは必ず起きるものとして扱う
  4. 上位モデルでなくていい作業を、先に決めておく。 テスト実行・整形・定型の集計は下位モデルに回す
  5. 枠が減ってきたら、止まらずに割り当て直す。 残りを何に使うかを決めるのは、契約したその日から始まる仕事です
