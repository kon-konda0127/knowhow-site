# なぜ重要か

これを読むと、「上位モデルを減らせるか」を意見ではなく自分の記録で判定できるようになる。

上位モデルを減らす話は、他人の環境の結論をそのまま持ち込んでも当たらない。契約しているものが違えば、選べる配置が違うからである。

# しくみ（なぜ効くか）

投稿の骨子はこうだった（要約）。

  • いちばん抽象度の高い層と、その次の設計の層と、検証の層と、実作業の層を分ける
  • 分けたうえで、層ごとに要求される能力に見合ったモデルを割り当てる
  • 実作業は GPT-5.6 の3ティア（Sol / Terra / Luna）に任せ、上位モデルの契約は減らす

効く理屈は分かる。層によって必要な能力は違うので、全部を最上位でやるのは払いすぎになる。この考え方そのものは、うちでも2026-08-14に別の投稿から取り込み済みである（→「Codexのsubagentごとにモデルを振り分ける」のノート）。

今回新しいのは「だから上位モデルの契約を減らす」という結論のほうで、そこが検証の対象になる。

# うちの体制ではこう使う

実測1: 契約があるのは4層のうち1層だけだった

投稿の振り分け表を、うちの手元で追えるか確かめた。

投稿の層割り当てうちで使えるか（2026-08-20 実測）
抽象GPT Pro経路なし
設計GPT の高推論 / 上位モデル上位モデルのみ
検証上位モデルあり
実作業Sol / Terra / Luna・稀に GrokLuna のみ。Sol・Terra は選択されていない。Grok はコマンド自体が無い

4層のうち3層は経路が無い。振り分け表としては採れない。

実測2: 最下位ティアを、実作業ではなく検証に置いていた

外部レビュー用のCLIの設定を開いたら、こうなっていた。

model = "gpt-5.6-luna"
model_reasoning_effort = "xhigh"

GPT-5.6 の最下位ティアに、推論の深さだけ最大を指定して使っていた。しかも用途は投稿が言う「実作業」ではなく、社外監査（自分たちの成果物を外から点検してもらう役）である。

意識して選んだ配置ではなかった。投稿を検証しようとして初めて、自分の設定を読んだ。

実測3: その最下位ティアが、内部の2者が見逃した欠陥を見つけていた

いちばん重かったのは 2026-08-15 の件である。

書き込み範囲の受け入れ基準として git check-ignore を使った負のテストを作り、品質をチェックする役のモデルも「合格」と報告した。ところがこのコマンドは、追跡済みのファイルに対しては設定がどう壊れていても「該当なし」を返す。つまり永久に合格し続ける、中身の無い検査だった。

実装を担当したモデルも、品質をチェックする役のモデルも見抜けず、社外監査で初めて発覚した。

ほかにも、測定の設計そのものを作り直させる指摘（成功率は簡単な仕事を寄せれば上がる、という指摘）や、テスト結果をパイプでつなぐと失敗が握り潰される、という指摘が出ている。いずれも最下位ティアからの指摘である。

実測4: ただし、その指摘をそのまま実装して2回壊した

同じ記録には逆の例も残っている。

  • 「モバイルで図の文字が読めない」という指摘を受けて最小幅を足したら、記事の本文が画面外にはみ出した（320px幅で21要素中20要素）
  • 「見出しと実データが合っていない」という指摘を受けて補足を書いたら、その補足自体が事実と違っていた

指摘が当たっていることと、指摘どおりに直して良いことは別である。

実測5: 「型があれば下位モデルでできる」は、条件付きで確認できた

2026-08-18 に、同じ作業を上位モデルと下位モデルで並行させる比較実験をした。記事の書き換えという題材で、測った6項目のうち差が出たのは1項目だけ（しかも下位モデルのほうが良かった）。重大な指摘と事実の誤りはどちらも0件。

ただし条件が付く。型が明文化されていて、事実の照合が軽い題材だった。事実照合の重い作業は未検証である。

# 投稿と逆になった点

投稿は検証を上位モデルに置き、実作業を下位ティアに置いていた。うちは検証に最下位ティアを置いて成果が出ている。

理由は推測だが、外から点検する役に必要なのは深い推論よりも「文脈を持っていないこと」なのだと思う。自分で作った人は、自分の思い込みごと点検してしまう。別系統のモデルであること自体が効いている可能性がある。

これはまだ確かめていない。同じ役を上位モデルにやらせて比べれば分かるが、今回はそこまでやっていない。

# よくあるミス・落とし穴

  • 他人の振り分け表を、契約を確かめずに真似しない。今回は4層のうち3層に経路が無かった。表として採れるかは、意見ではなくコマンドの有無と設定ファイルで決まる
  • 「上位が不要」という結論だけを持ち帰らない。投稿には測定値が無い。持ち帰るなら、自分の記録のどこがそれを支持し、どこが支持しないかまで見る
  • モデルの名前を、知らないまま書かない。今回 Sol / Terra / Luna は調べるまで何か分からなかった。知らない名前を推測で説明すると、記事全体の信用が落ちる
  • 外部レビューの指摘を、そのまま実装しない。当たっている指摘でも、直し方まで正しいとは限らない。うちでは2回、直した結果が新しい不具合になっている
  • 自分の設定を読まずに「うちはこうしている」と書かない。今回いちばんの発見は、自分たちが既に最下位ティアを使っていたと気づいていなかったことだった
