# なぜ重要か

これを読むと、「上限で止まる」問題がどこまで解決したのかを、期待をふくらませずに把握できる。

止まる場所が5時間の枠なのか週の枠なのかで、効き方はまるで違う。週の枠で止まっている人には、この機能はたぶん効かない。

# しくみ（なぜ効くか）

  • 上限に当たった時、これまではその場で止まり、人が打ち直す必要があった
  • 新しい挙動では、リセットの時刻まで待ってから、止まった続きを自分で再開する
  • 効くのは「人がその場にいなくてよくなる」点。夜に長い作業を投げて寝る使い方と噛み合う

# うちの体制ではこう使う

実測1: うちのバージョンには入っている

投稿は 2.1.234 の話で、うちは本日 2.1.233 から 2.1.237 へ上げた。2.1.234 をまたいでいるので対象に含まれる。

実行ファイルの中に、該当する文字列があることを確認した。

ただし、この確かめ方自体が一度間違っていた。最初はパッケージのフォルダを普通に検索して「0件」と出た。そこで既に存在すると分かっている機能の名前（遠隔操作・ステータス行）を同じ方法で探したところ、そちらも0件だった。つまり検索方法のほうが壊れていた（本体が300MB超の実行ファイルで、テキストとして読ませる指定が要る）。

指定を直すと、対照に置いた2つは正しく見つかり、本題の語も見つかった。対照を置かなければ「機能が無い」と誤って結論していた。

実測2: 投稿の説明と2点食い違う

項目投稿裏取りした情報
どの上限か週の上限5時間の枠（リセットで再開）
切り替え場所/config上限バナーのチェックボックス（既定でオン）

この差は小さくない。週の枠で止まっている人が「これで解決する」と読むと、期待が外れる。

実測3: 未検証の部分をはっきりさせる

実際に上限へ当たった時にどう動くかは、確かめていない。上限に当たらないと試せないためで、当たるまで待つしかない。

  • 「機能が存在する」＝確認できた
  • 「投稿の説明と食い違う点がある」＝第三者の記事2本で確認
  • 「実際にこう動く」＝未検証

# よくあるミス・落とし穴

  • 「どの上限か」を確かめずに喜ばない。5時間の枠と週の枠は別物で、効き方が違う
  • 速報の記事は、切り替え場所のような細部がずれやすい。設定を探して見つからない時は、まず出どころを疑う
  • 「ソフトの中に無い」と結論する前に、探し方が正しいか確かめる。今回は既に存在すると分かっている機能を対照に置いて初めて、検索方法のほうが壊れていると分かった
  • 未検証の部分を書き残す。「存在する」と「思ったとおり動く」は別で、後者は上限に当たるまで分からない
