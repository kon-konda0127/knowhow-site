# Claude Code HTML出力をコンサル品質に整えるスキル

カテゴリ: AI開発 > Claude Code活用
タグ: #ClaudeCode #スキル #HTML出力 #資料作成

## なぜ重要か

スキル（AIに読ませる作法書）を1つ入れるだけで、AIのHTML資料が「枠と箱だらけの野暮ったい見た目」から「余白と文字の階層で見せるコンサル資料級」に変わる。AIの生成物が没個性なテンプレ見た目（いわゆるAI slop）に収束する問題への、具体的で再現可能な対策例。

## しくみ（なぜ効くか）

- スキルとは、特定の頼み方をした瞬間だけAIが読み込む「作法書」。この `html-report-design` スキルは**「HTMLで出して」と言った時だけ**働く
- 中身は「禁止と強制」の組み合わせ:
  - 禁止: 枠線・グラデーション・絵文字（AIが多用しがちな装飾）
  - 強制: 完成済みCSSを使う／各セクションは「見出し→結論1文→根拠」の順
- 図解は5つの型（矢羽根/ロードマップ/フレームワーク表/バブル/滝グラフ）から選ばせ、自由に描かせない
- 配色は脇役グレー＋主役の濃紺1色。凡例を作らずグラフに直接ラベルを書く。アクセント色だけ会社カラーに差し替え可能
- 効く理由: 「センス良く」という曖昧な指示ではなく、**判断基準を作法書として渡す**から毎回同じ品質が出る。A4印刷でそのまま配布できる想定

## うちの体制ではこう使う（実体験との接続）

- 「AI生成UIは放っておくとテンプレ的な見た目に収束する」問題は、当サイトの開発でも実際に直面し、チーム規程に「配色・余白・タイポグラフィの判断基準を毎回明示的に適用する」というルールを入れて対処している
- このスキルはその「判断基準の明文化」を資料デザイン領域でパッケージ化したもの。発想は同じで、対象がUIか資料かの違い

```bash

```

または Claude Code に「このリポジトリの skills/html-report-design を ~/.claude/skills/ に入れて」と依頼する方法も紹介されている。

## よくあるミス・落とし穴

- スキルなしで「HTMLで出して」と頼むと枠・グラデ・絵文字まみれになる
- Claude Code専用ではない（ChatGPT派はSKILL.mdの中身をコピペしても動くとされる ※要確認）
